# Спецификация модуля стеновых прогонов

## Статус и границы

Это проектная спецификация без реализации. Сценарий 21604 имеет статус
`provisional-author-restored-inputs`: расчётчик восстановил две книги запусков,
но первоначальные файлы расчёта 21604 не сохранились.

Первая версия должна рассчитывать обычные стеновые прогоны под профлист:

- продольную и торцевую стены отдельными запусками;
- угловую и рядовую зоны;
- выбор ПП/ПС и МП350/МП390;
- шаг ригелей, число рядов, длину и массу профилей;
- количество и массу кронштейнов;
- уголки и стеновой крепёж отдельными позициями.

Пока исключены снеговой мешок, стоимость проёмов, автоматическое обновление
цен 1С и ручные слагаемые кронштейнов 21604.

## Входной контракт

```ts
type WallPurlinsInput = {
  city: string;
  responsibilityFactor: number;
  standard: "СП 20.13330" | "СП РК EN";
  terrainType: string;
  windPressureKPa: number | null;
  spanM: number;
  buildingLengthM: number;
  buildingHeightM: number;
  wallOrientation: "longitudinal" | "end";
  wallLengthM: number;
  layoutHeightM: number;
  postSpacingM: number;
  decking: string;
  allowedFamilies: Array<"ПП" | "ПС" | "ТПП" | "ТПС">;
  allowedSteelSeries: Array<"МП350" | "МП390">;
  cornerStepOverrideMm: number;
  regularStepOverrideMm: number;
  cornerThicknessMm: number | null;
  regularThicknessMm: number | null;
};
```

Реконструированный ввод обязан сохранять `provenance` и не может становиться
неявным значением по умолчанию.

## Выходной контракт

```ts
type WallPurlinZoneResult = {
  zone: "corner" | "regular";
  lengthM: number;
  profile: string | null;
  steelSeries: "МП350" | "МП390" | null;
  scheme: string | null;
  stepMm: number | null;
  rowCount: number | null;
  profileLengthM: number | null;
  profileMassKg: number | null;
  bracketCount: number | null;
  bracketMassKg: number | null;
  workbookSelectionMassKg: number | null;
  status: "ok" | "no-solution" | "source-blocked";
};
```

Масса профилей, масса кронштейнов и показатель выбора Excel остаются
раздельными. `Лист1!E51` суммирует `E49:E50`, но этот результат нельзя называть
физической полной массой: он не равен сумме `I49:I50` и `H49:H50`, а для
продольной стены местами меньше массы профиля. До разбора слагаемых `TQ7`
поле хранится как `workbookSelectionMassKg`.

## Расчётная последовательность для будущего переноса

1. Получить ветровую нагрузку по городу, нормативу и местности.
2. Вычислить угловую зону с граничным условием отношения `0,5`.
3. Получить рядовую зону как остаток длины стены.
4. Сформировать кандидаты разрешённых профилей и материалов.
5. Для каждого шага вычислить ряды, длину, кронштейны и массу.
6. Выбрать минимальную допустимую массу.
7. Умножить результат на две стены каждого типа на уровне проекта.
8. Добавить уголки и крепёж отдельными позициями ведомости.

## Заблокированные правила

| Правило | Причина | Требуемое решение |
|---|---|---|
| Снеговой мешок `Q80:S81` | `#REF!` в четырёх книгах | неповреждённая книга или формулы автора |
| Кронштейны `24+10,5+18+45` | ручные числа не расшифрованы | пояснение расчётчика |
| Третья продольная линия уголка | назначение не подписано | инженерная приёмка |
| Проёмы | 21604 не уменьшает подсистему | подтвердить намеренность |
| ТПП/ТПС против ПП/ПС | версии отличаются переключателями | утвердить допустимые семейства |

`scripts/oracle/inputs/21604-wall-purlins.json` и
`scripts/oracle/inputs/wall-purlin-candidates.json`.

## Условия начала реализации

1. Две книги 22317 пересчитаны Excel COM только для чтения — выполнено.
2. SHA-256 до и после совпадают — выполнено.
3. Сохранённые и пересчитанные результаты совпадают — выполнено.
4. Снеговой мешок возвращает `source-blocked`, а не фиктивный результат.
5. Приняты сценарии с нулевой и ненулевой угловой зоной.
