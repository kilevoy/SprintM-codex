# Ядро калькулятора ограждайки: извлечённая схема

Источник: `Y:\Предварительные расчеты\Калькуляторы\Калькулятор ограждайки v1.5.xlsx`.

SHA-256 исходной книги: `4A9343A1E3149954DEC0F91D5398528F18016A8423EC204CE2B92A59F612DEAF`.

Книга содержит листы `Лист1`, `Расчет Угловая`, `Расчет Рядовая`, `несушки`,
`Ветер по СП`, `Ветер по EN`. Всё ниже получено через Excel COM
(`CalculateFullRebuild`, книга открыта только для чтения, SHA-256 до и после
совпадает — файл не изменялся).

## Статус (обновлено после полного разбора матрицы)

Алгоритм автоподбора профиля и шага **полностью понят и воспроизведён**
чистой функцией `selectWallPurlinProfile`
(`src/calc/wallPurlins/selectWallPurlinProfile.ts`), сверенной с живыми
ячейками книги до последней значащей цифры на двух независимых зонах одного
расчёта (см. «Сверка» ниже). Это **не** равносильно подтверждённому
паритету на реальном объекте — коэффициент ветровой нагрузки зоны (C3),
который в Excel собирается из высотного коэффициента k(ze), коэффициента
пульсации и корреляции, в SprintM ещё не реализован; см. «Что осталось» в
конце файла.

## Передача входов

`Лист1` передаёт на два расчётных листа:

- длину расчётной стены `B11`;
- высоту расчётной стены `B12` (для торцевой стены — высота по коньку, для
  продольной — высота по карнизу; выбор высоты — ответственность вызывающей
  стороны, не самого калькулятора);
- шаг стоек (шаг рам) `B13`;
- тип покрытия `B18`, профлист `B19`;
- минимальный/максимальный шаг зоны: угловая `B23:B24`, рядовая `B28:B29`
  (`B24`/`B29` — авто-расчёт по таблице допустимых пролётов профнастила
  `B109:B158`, если `B22`/`B27` = 0);
- ограничения профиля `B32` (0 = коэффициент момента берётся из столбца `O`
  каталога, иначе используется как явное число), `B33`/`B34` (макс/мин высота
  профиля, столбец `N`), `B35`/`B36` (мин/макс класс толщины, столбец `M`,
  «любая» → 0..100).

## Структура расчётных листов

Строки **7–870** (864 строки) на обоих листах — это **общий статический
каталог профилей** (те же значения на «Расчет Угловая» и «Расчет Рядовая»):
столбец `G` — порядковый номер (1..864), `H` — семейство (ПП/ПС/ПГССигма/
ТПП/ТПС/ТПГС), `I` — разрешено ли семейство (см. ниже), `J` — тип сечения
(`]`/`][`/`[]`/`[-]`), `K` — разрешён ли тип сечения, `L` — требуется ли
раскрепление стойками («нет»/«да»/«есть»), `M` — класс толщины, `N` — высота
профиля, мм, `O` — коэффициент использования по умолчанию, `P` — тип
кронштейна (МП220/350/390), `Q` — разрешён ли кронштейн, `R`/`S` — можно ли
использовать профиль без дополнительных стоек, `T` — масса стойки (кг, если
требуется), `U` — требуемая толщина утепления, мм, `V` — полное имя профиля,
`W`/`X` — базовый и предельный изгибающий момент (`X` = «Пред М», несущая
характеристика), `Y`/`Z` — масса профиля/сечения на метр, `AA` — масса
узловой сборки.

Этот каталог уже извлечён воспроизводимым скриптом
`scripts/extract_wall_purlin_profiles.py` → `src/data/wallPurlinProfiles.generated.json`
(поля `family`, `sectionType`, `bracing`, `thickness_mm`(=M), `height_mm`(=N),
`usageFactor`(=O), `material`(=P), `insulation_mm`(=U), `capacity_X`(=X),
`jointFactor_Q`(=Q), `jointFactor_S`(=S), `massProfile_kg_m`(=Y),
`massSection_kg_m`(=Z), `jointMass_kg`(=AA)).

**Фиксированные (не зависящие от сценария) таблицы допустимости** —
`Лист1!V89:W94` (семейство), `V97:W99` (кронштейн), `V102:W105` (тип
сечения), `W107` (глобальный флаг «без стоек»). В книге v1.5 это обычные
значения, не формулы:

- семейства: ПП=да, ПС=да, ПГССигма/ТПП/ТПС/ТПГС=нет;
- кронштейны: МП220/350/390 — все да;
- типы сечения: `]`/`][`/`[]`/`[-]` — все да;
- `W107=да` ⇒ `S_r = R_r` для каждой строки всегда (без дополнительной
  сценарной зависимости). В каталоге v1.5 **все** строки с
  `bracing="да"` имеют `R=S=false` — то есть варианты «+ стойки» сейчас
  **никогда** не проходят проверку `S`, вне зависимости от сценария (232 из
  864 строк невыбираемы по построению книги).

Столбцы `AWX:BGN` (251 столбец, заголовок строки 2 — шаг от 500 до 3000 мм
с шагом 10 мм) — это **представление**, а не собственно расчётная матрица:
`AWX7 = SMALL(<столбец‑спутник для этого шага>$7:$870, $AWW7)`, где
`AWW7=G7=1` — то есть `AWX7` это 1-е по возрастанию (минимальное) значение
среди всех 864 профилей на этом шаге. У каждого из 251 столбцов есть
собственный «столбец-спутник» (скрытый, с плавающим названием — `TQ` для
шага 500, `WZ` для 1370, `XA` для 1380 и т.д.), который на всех 864 строках
считает для СВОЕГО шага:

```excel
скрытый_столбец$row = IF(<JW-условие для этого шага и строки>=0,
  999999999,
  TQ$4*Z_row + Y_row*Лист1!$B$13 + TQ$3*AA_row
    + G_row/1000000 - <шаг>/1000000000 + Y_row*Лист1!$B$13 + T_row)
```

`JW`-условие для строки `row` и шага `s` (то же самое на угловой и рядовой
зоне, только границы шага и `C3` — свои):

```excel
AND(
  s >= Лист1!B23(или B28), s <= Лист1!B24(или B29),
  I_row, K_row,                          -- семейство/тип сечения разрешены
  M_row <= M4, M_row >= M5,              -- класс толщины (Лист1!B35:B36)
  N_row >= Лист1!B34, N_row <= Лист1!B33, -- высота профиля
  Q_row,                                 -- кронштейн разрешён
  U_row = <требуемое утепление>,         -- 0 для профлиста
  AD7(row, s) <= 1,                      -- коэффициент использования
  IF(Лист1!B10="нет", TRUE, ...),        -- только для сэндвич-панели, для профлиста всегда TRUE
  S_row                                  -- допустимо без доп. стоек
)
```

где `AD7(row, s) = moment(s) / X_row` и

```excel
moment(s) = C3 * windCoefficient(tributaryWidth(s)) * (s/1000) * Лист1!B13^2 / 8
tributaryWidth(s) = (s/1000) * Лист1!B13
```

**Важно:** `windCoefficient` — это НЕ линейная интерполяция, а
приближённый (ступенчатый) `MATCH(..., 1)` по таблице `'Ветер по
СП'!V5:AD6`: берётся значение в ближайшей МЕНЬШЕЙ ИЛИ РАВНОЙ точке таблицы.
Часть точек таблицы (3, 4, 7.5, 15 м) уже посчитана интерполяцией при
заполнении книги, но заново на лету при поиске не интерполируется. Проверено
на живых ячейках: тяготеющая ширина 8.22 м и 8.28 м обе дают коэффициент 0.8
(ближайшая меньшая точка — 7.5 м), а НЕ промежуточное значение между 0.8 и
0.75, которое дала бы линейная интерполяция. Опорные точки (ширина, м →
коэффициент): 0→1, 2→1, 3→0.95, 4→0.9, 5→0.85, 7.5→0.8, 10→0.75, 15→0.7,
20→0.65 (после 20 м — 0.65).

`C3` — коэффициент ветровой нагрузки зоны:

```excel
C3(угловая) = 'Ветер по СП'!F7 * Лист1!B3     -- F7 = C9*C11*(1+C12)*F6*C13
C3(рядовая) = 'Ветер по СП'!G7 * Лист1!B3     -- G7 = C9*C11*(1+C12)*G6*C13
```

где на листе «Ветер по СП»:

```excel
C8  = MAX(5; Лист1!B8)     -- высота по коньку, не ниже 5 м
C9  = Лист1!B17            -- w0 ветрового района, кПа
C4  = Лист1!B16            -- тип местности А/В/С
C11 = k(ze)                -- СП 20.13330 табл. 11.2, линейная интерполяция по высоте
C12 = ζ(ze)                -- СП 20.13330 табл. 11.4, линейная интерполяция по высоте
C13 = γf = 1,4
F6  = 2,2 (угловая зона)   G6 = 1,4 (рядовая зона)  -- пиковые аэродинамические
                                                       коэффициенты, «без ν»
```

Коэффициент пространственной корреляции ν в C3 **не входит** — подпись
`F4` в книге прямо говорит «Пиковая нагрузка без v». Это перенесено в
`src/calc/wallPurlins/zoneWindPressure.ts` (обе таблицы СП — там же) и
сверено с книгой: k(ze)=0,66 и ζ(ze)=1,053 на 10,5 м для типа «В»,
F7=1,25200152, G7=0,79672824, C3=1,001601216 и 0,637382592 при γn=0,8.

Интерполяция по высоте здесь честно линейная (в отличие от AD4): блоки
`N52:P63` и `W52:AB63` содержат формулы вида
`=K52+(K53-K52)*($C$10-$J52)/($J53-$J52)`, а `MATCH` с приближённым поиском
выбирает отрезок, в который попала высота.

## Границы шага: таблица пролётов обшивки

```excel
Лист1!B24 = ЕСЛИ(B22=0; ИНДЕКС(B109:B158; ПОИСКПОЗ(E22; N109:N158; -1); 1); B22)
Лист1!B29 = ЕСЛИ(B27=0; ИНДЕКС(B109:B158; ПОИСКПОЗ(E27; N109:N158; -1); 1); B27)
E22 = 'Расчет Угловая'!D5        E27 = 'Расчет Рядовая'!D5
D5  = C3 * 'Ветер по СП'!AB6 * Лист1!B3
```

`B109:B158` — пролёты 600…3000 мм с шагом 50, `C109:M158` — допустимая
нагрузка для каждой из 11 марок обшивки, `N` — столбец выбранной марки.
Поиск с `-1` по невозрастающему столбцу даёт **самый большой пролёт,
который ещё держит расчётную нагрузку**.

Два момента, которые воспроизводятся «как есть», потому что эталон —
формула книги:

- `'Ветер по СП'!AB6` = 0,75 — это коэффициент таблицы на грузовой площади
  10 м², зафиксированный ячейкой, а не пересчитываемый по шагу;
- `γn` входит в `D5` **дважды**: один раз внутри `C3`, второй раз явным
  множителем `Лист1!B3`.

Таблица извлечена воспроизводимым скриптом
`scripts/extract_wall_decking_spans.py` →
`src/data/wallDeckingSpans.generated.json` (с SHA-256 исходной книги).

## Результат: BGQ/BGS/BGT/BGU

```excel
BGQ7 = MIN(AWX7:BGN7)                                    -- глобальный минимум по (профиль×шаг)
BGS7 = INDEX($AWX$2:$BGN$2, 1, MATCH(BGQ7, AWX7:BGN7, 0)) -- шаг, на котором достигнут минимум
BGT7 = <имя профиля, дающего минимум на шаге BGS7>        -- через служебный столбец-спутник этого шага
BGU7 = <тип кронштейна того же профиля>
BGR7 = BGQ7 * ADI1   -- ADI1(угловая)=Лист1!E24/B13, ADI1(рядовая)=ROUND(Лист1!E29/B13,1); нигде дальше не используется
```

`Лист1` полностью автоматически забирает эти значения (никакого ручного
переноса в самом Excel нет):

```excel
Лист1!B49 = 'Расчет Угловая'!BGT7      Лист1!B50 = 'Расчет Рядовая'!BGT7
Лист1!C49 = 'Расчет Угловая'!BGU7      Лист1!C50 = 'Расчет Рядовая'!BGU7
Лист1!D49 = 'Расчет Угловая'!BGS7      Лист1!D50 = 'Расчет Рядовая'!BGS7
Лист1!E49 = 'Расчет Угловая'!BGR7      Лист1!E50 = 'Расчет Рядовая'!BGR7
```

Передача результата в ведомость (углы обозначений `K49`/`K50` — тип сечения
выбранного профиля через `INDEX/MATCH` по имени `B49`/`B50`):

```excel
F49 = CEILING.MATH(B12*1000/D49,1) + IF(OR(K49="[]",K49="][",K49="[-]"),0,1)
G49 = F49*E24/B13                                    -- E24 = длина угловой зоны
H49 = INDEX('Расчет Угловая'!AA7:AA870, MATCH(B49,V7:V870,0), 1) * G49
I49 = F49*E24*INDEX('Расчет Угловая'!Z7:Z870, MATCH(B49,V7:V870,0), 1)

G50 = CEILING.MATH(F50*ROUND(E29/B13,1),1)           -- E29 = длина рядовой зоны
H50/I50 — аналогично, по строке B50
```

Длина угловой зоны (одна из двух угловых зон стены, формула на листе
«Расчет Угловая»!C8):

```excel
e = MIN(Лист1!B6(пролёт), 2*Лист1!B8(высота по коньку))    -- 'Ветер по СП'!J30
cornerZoneWidth = e/5                                        -- 'Ветер по СП'!J31
C8(угловая) = 2 * IF(cornerZoneWidth/B13 < 0.5, 0, CEILING.MATH(cornerZoneWidth/B13,1)*B13)
C8(рядовая) = Лист1!B11 - C8(угловая)
```

Это стандартная геометрия угловой/торцевой зоны ветра по СП 20.13330
(приложение с зонами давления).

## Сверка на реальных объектах

Расчётчик сохраняет копию калькулятора рядом с объектом — в ней и его
собственные входы `Лист1`, и подобранные книгой профили. Это лучше
реконструкции по ведомости: восстанавливать нечего.

Найдено шесть таких копий по трём независимым объектам; все они собраны в
`scripts/oracle/inputs/wall-purlin-object-runs.json` (имя файла, SHA-256,
подтверждение, что книга не изменилась) и сверяются скриптом
`scripts/oracle/compare_wall_purlin_objects.mjs`
(`npm run check:wall-purlin-objects`).

| Объект | Стена | Шаг стоек | Зоны, м | Подбор книги |
|---|---|---|---|---|
| 21604 Кропоткин 18×48, γn=1, w0=0,48 | торцевая 18×9,75 | 6 | 12,00 / 6,00 | `[-]ПС145х45х1,5`/МП390 шаг 1290, 8 рядов; `[-]ПС145х45х1,2`/МП350 шаг 1480, 7 рядов |
| 21604 | продольная 48×7,5 | 5,35 | 10,70 / 37,30 | `[-]ПС145х45х1,2`/МП350 шаг 1120, 7 рядов; то же шаг 1500, 5 рядов |
| 21876 Каргалейка 12×30, γn=0,8, w0=0,3 | продольная 30×4,8 | 6 | 0,00 / 30,00 | `[]ПП 145x45x1,2`/МП350 шаг 1500, 4 ряда |
| 21876 | торцевая 12×6,5 | 4 | 8,00 / 4,00 | `[]ПП 145x45x1,2`/МП350 шаг 1500, 5 рядов |
| 22317 Благовещенск 12×45, γn=1, w0=0,3 | продольная 45×6,8 | 6 | 0,00 / 45,00 | `[]ПП 170x45x1,2`/МП350 шаг 1450, 5 рядов |
| 22317 | торцевая 12×7,4 | 6 | 0,00 / 12,00 | `[]ПП 170x45x1,2`/МП390 шаг 1500, 5 рядов |

`computeWallPurlinsAuto` воспроизводит все шесть расчётов целиком: 90 из
90 величин — максимальный шаг, протяжённости зон, профиль, кронштейн, шаг,
число рядов, масса зоны и итог на стену.

Что эти файлы попутно доказали (раньше это были догадки):

- **`Лист1!B7` — длина здания, а не ширина считаемой стены.** На торце
  21604 в `B7` стоит 48 (длина), при том что сама стена 18 м, и
  `e = MIN(48; 2·9,75) = 19,5` даёт ровно те 12,00 м угловой зоны, что
  показывает книга.
- **Шаг стоек задаётся отдельно для каждой стены.** На торце 21876 это 4 м
  (12 м торца = 3 пролёта), а на продольной — 6 м; на 21604 — 6 и 5,35.
  Это не шаг рам здания, а шаг стоек фахверка конкретной стены.
- **Высота стены: торец — по коньку, продольная — по карнизу**, как и
  записано в передаче: 21604 — 9,75 и 7,5 при высоте здания 9,75.
- **Высоту профиля расчётчик обычно зажимает** (`B33 = B34`): 145 мм на
  21604 и 21876, 170 мм на продольных стенах 22317. Иначе обшивка не
  ляжет в одну плоскость. На торце 22317 верхняя граница поднята до 500.

Сверка объектных **ведомостей** (не калькуляторов) дополнительно совпала
там, где её удалось проверить: 21876 — 720 п.м. профиля и 90 кг
кронштейнов, 22258 Хабаровск — 644 + 200 п.м. и 117 кг кронштейнов, причём
в ведомости 22258 масса кронштейнов записана как `(36+15+7.5)*2`, и все три
слагаемых сходятся с расчётом по зонам. Для 22258 своей копии калькулятора
не нашлось, поэтому её входы восстановлены по ведомости — это
единственный случай с реконструкцией.

## Подключение к расчёту объекта

`computeProject` принимает необязательный блок `wallPurlinsAuto` и считает
обе стены сразу: продольную по карнизу и на длину здания, торцевую по
коньку и на пролёт. Результат — `wallPurlinsAuto.takeoff`: строки
ведомости, сгруппированные по профилю, и кронштейны.

Ведомость считает **погонные метры профиля**, а не линий прогонов: у
парного сечения (`[]`, `][`, `[-]`) на метр линии идёт два метра профиля.
Множитель берётся из самого каталога — отношением массы сечения к массе
профиля, а не по списку обозначений.

Два входа блока задаются, а не выводятся:

- **`profileHeight_mm`** — зажим высоты профиля (`Лист1!B33 = B34`).
  Вывести не удалось: правило «взять минимальную высоту, которая проходит
  везде» даёт 220 мм на 21604 и 170 мм на 21876, тогда как расчётчик на
  обоих поставил 145 мм, добрав толщиной. Это его решение (высота профиля
  на стене должна быть одна, иначе обшивка не ляжет в плоскость), и
  выдумывать за него правило здесь нельзя.
- **`gablePostSpacing_m`** — шаг стоек фахверка торца. По умолчанию
  выводится из `facadePostCount`: пролёт / (стоек на торец + 1). Это
  сходится с 21604 (18 м → 6 м) и 21876 (12 м → 4 м), но на 22317
  расчётчик взял 6 м там, где правило даёт 4, поэтому вход остаётся
  переопределяемым.

Сквозной прогон `computeProject` по 21876 даёт те же 720 п.м. профиля, что
и ведомость объекта.

### Расхождение внутри исходных данных 21876

Ведомость объекта и сохранённая расчётчиком копия калькулятора по тому же
объекту **не сходятся между собой** по кронштейнам: копия посчитана при
шаге стоек торца 4 м и даёт 105 кг, а ведомость записана под 6 м и даёт
90 кг. Метраж профиля (720 п.м.) при этом одинаков, потому что обе зоны
торца берут один профиль и одинаковое число рядов. SprintM воспроизводит
оба варианта точно — расходятся сами документы, а не расчёт.

## Проёмы: площадь режут, прогоны — нет

В «Калькуляторе ограждайки» полей проёмов нет вообще, а в ведомости 21876
метраж прогонов записан формулой по целым стенам
(`=5*2*12*2 + 4*2*30*2`). То есть прогон идёт поверх проёма, вырезается
только лист обшивки: вычет площади профнастила есть, вычета прогонов —
нет. Закреплено тестом в `src/calc/project/wallPurlinsAuto.test.ts`.

## Оконные ригели

Сечение выбирается по ВЫСОТЕ окна (`windowRigelByHeight`):
до 1,5 м — труба 80×4, от 1,5 до 3 м — труба 120×4, выше 3 м — витраж,
автоматически не считается. Трубы обычные чёрные, цена — «Перекупные» →
«Нелегированная сталь» → «Труба».

Правило именно по высоте: от неё зависит грузовая площадь ригеля, пролёт
которого равен шагу рам, и «выше 3 м — витраж» осмысленно только для
высоты — широкое окно это ленточное остекление, у него в подборщике своя
строка `O27`.

Масса обрамления считается формулой подборщика (книга «Таблица по подбору
сечений … версия 1,5», `Лист1!O26`):

```excel
O26 = (E24*B7 + E37*(2*B6 + B7)) * кол-во
```

`E24`/`E37` — погонные веса нижнего и верхнего ригелей, `B7` — шаг рам,
`B6` — высота окна: нижний ригель идёт на пролёт шага рам, верхний — на
две стойки по высоте окна плюс перемычку в шаг рам. Надбавки 1,05 в этой
строке нет, в отличие от соседних строк по воротам и дверям.

## Что осталось (по-прежнему provisional)

1. Стеновые прогоны **не входят в стоимость проекта**. Цена самого
   профиля сверена с ведомостью 21876 до копейки (313,95 против 314,0 и
   402,15 против 402,2), но цены кронштейнов в SprintM нет вовсе, поэтому
   раздел стоит рядом с итогами, а не внутри них.
2. Высоту стен `computeProject` выводит сам (карниз из `height_m`, конёк —
   по своему правилу уклона), и это не обязано совпадать с тем, что
   расчётчик вбивает руками: на 21876 в его копии стоит 4,8 м при 4,5 м в
   шапке ведомости. Паритет на 90 величин получен на ЕГО входах.
3. Правило сечения оконного ригеля перенесено со слов расчётчика и на
   объектных ведомостях не сверялось: обрамление попадает там в общую
   тонну «Конструкции из труб» вместе с распорками, и отдельной строки по
   окнам в ведомости нет.
4. Утеплённые покрытия («наша послойка») сознательно не поддерживаются:
   там включается ограничение шага по `Лист1!D10:F10`, которого нет в
   профлистовой ветке, и ни на одном расчёте это не проверялось.

## Живой оракул: прогон сценариев через саму книгу

`scripts/oracle/run_wall_purlin_calculator.ps1` принимает JSON со
значениями ячеек `Лист1` (один сценарий или массив), **копирует книгу во
временный каталог**, проставляет входы в КОПИИ, вызывает
`CalculateFullRebuild`, читает `Лист1!B49:K50`, зоны и ветровой блок,
закрывает копию без сохранения и удаляет её. SHA-256 оригинала снимается
до и после и попадает в отчёт: если он изменился, результат недействителен.
Оригинал на запись не открывается никогда.

`scripts/oracle/compare_wall_purlin_calculator.mjs` подаёт те же входы в
`computeWallPurlinsAuto` и сравнивает построчно все величины — профиль,
кронштейн, шаг, максимальный шаг, длины зон, число рядов, кронштейны,
массы, `C3` и `D5`.

```powershell
powershell -File scripts/oracle/run_wall_purlin_calculator.ps1 `
  -WorkbookPath '<путь к книге>' `
  -InputPath scripts/oracle/inputs/wall-purlin-calculator-scenarios.json `
  -OutputPath scripts/oracle/expected/wall-purlin-calculator.json

npx vite-node scripts/oracle/compare_wall_purlin_calculator.mjs -- `
  scripts/oracle/expected/wall-purlin-calculator.json
```
